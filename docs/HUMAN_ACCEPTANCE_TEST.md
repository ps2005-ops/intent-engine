# Tester pack — company briefing tool

You have been given a web address and nothing else. That is deliberate: if you
need someone to explain the product to you, it has failed, and we would rather
find that out from you than from a customer.

Please do not ask the person who gave you this link for help. If you get stuck,
**write down where you got stuck and stop** — that is the single most valuable
thing you can report.

Expect this to take **20–30 minutes**.

---

## What to do

Work through these in order. After each one, jot a note — a few words is fine.

**1. Open the link and read whatever appears first.**
Before clicking anything: in your own words, what do you think this does?
Write it down before you find out whether you were right.

**2. Analyse Palantir.**
Use whichever route the page offers. Wait for it to finish.

**3. Read the briefing.**
Do not skim ahead to anything longer. Just read what it gives you first.

**4. From that briefing alone, write down:**
- the main thing it is claiming about the company;
- one risk or tension it names;
- one decision a leader would make differently because of it.

If you cannot find one of these, write "couldn't find it". That is a result,
not a failure on your part.

**5. Open the presentation and move through every slide.**
Try the arrow keys as well as the buttons.

**6. Analyse Shopify.** Read its briefing too, more quickly this time.

**7. Try Sony.**
Note what happens. Anything is a valid outcome — a briefing, a partial result,
or a refusal. Write down whether what happened seemed reasonable to you.

**8. Ask five follow-up questions in your own words.**
Use whatever you would actually type. Some suggestions if you want them:
- What does this company do?
- Why does this matter?
- What evidence weakens this?
- What should I watch?
- Explain that more simply.

**9. Open one citation** — click through from a claim to the source behind it.
Did it show you what you expected?

**10. Send feedback** using whatever the page offers.
If there is no way to do that, note it.

## Questionnaire

1–5 where **1 = strongly disagree** and **5 = strongly agree**.

| # | Statement | 1–5 |
|---|---|---|
| 1 | Within a minute of arriving I understood what this does. | |
| 2 | The first briefing told me something I could use. | |
| 3 | I believe what it told me. | |
| 4 | Reading it took about as long as I expected. | |
| 5 | I could show the presentation to someone without editing it. | |
| 6 | The follow-up answers addressed what I actually asked. | |
| 7 | The evidence behind the claims looked credible. | |
| 8 | I would use this before a real meeting. | |
| 9 | When it could not do something, it said so clearly. | |
| 10 | Nothing on screen confused me or looked broken. | |

**Written answers — these matter more than the numbers.**

11. What did you think this did, before you found out? (from step 1)

12. Where, if anywhere, did you get stuck or confused?

13. Was anything on screen unreadable, broken, or odd-looking? Which page?

14. Did anything read as filler — text that took up space without telling you
    anything?

15. Did any answer feel like it dodged your question?

16. What was the single most useful thing it told you?

17. What was the single least useful?

18. Would you trust this enough to repeat one of its claims out loud in a
    meeting? Why or why not?

19. If you could change one thing, what?

20. Anything that surprised you — good or bad?

## What we are watching for

Not for you to fill in — this is so you know what counts as a finding.

A run that ends in a refusal is not a bug if the refusal explained itself. A
briefing that is short is not a bug if it is short and true. **Text that looks
like an answer but says nothing is the worst outcome**, and it is the hardest
for us to see from the inside, because we know what it was supposed to say.

So if a sentence sounds impressive and you cannot say what it means — please
write that one down.
