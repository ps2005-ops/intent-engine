# Reconstruction audit — could someone rebuild this from the repository alone?

*§62. Answered with evidence, not assertion. Re-run the checks below after any
change to what a conclusion rests on.*

---

## The question

If this machine disappeared and the repository were cloned tomorrow, could
another engineer reconstruct the product, the economic world model, the
company state, the forward ledger schema, the `PRE_CALIBRATION` state, the
research conclusions, the retired hypotheses, the learning metrics, the
deployment architecture, the demo proof and the validation methodology?

## The regeneration path

Every derived number in the documents above comes from a script in this
repository, and each can be re-run from a clean clone:

```
scripts/publish_econ_state.py --root data     # the shared economic state
scripts/run_world_model.py                    # relations and implications
scripts/run_relation_and_ceo.py               # relation evaluation, CEO Q&A
scripts/open_relation_expectations.py         # the relation -> expectation seam
scripts/run_decision_value.py                 # the 60-case A/B
scripts/run_product_parity.py                 # the product consumer, same cases
scripts/close_v3.py                           # the three closure ledgers
scripts/break_proofs_v5.py                    # research break proofs
scripts/break_proofs_product.py               # product break proofs
scripts/live_econ_matrix.py                   # the deployed matrix
```

None of them needs a secret. `live_econ_matrix.py` needs the internet and the
deployed preview; everything else runs offline.

## What is deliberately NOT in the repository

- secrets and credentials (Render dashboard only)
- private runtime data and tenant state
- ephemeral caches

## Known gaps in reconstructability

- **The deployed instance's runtime disk is ephemeral.** Guest analyses do
  not survive a redeploy, and the live reports capture their content rather
  than their run ids being re-openable. This is recorded in each report.
- **`MARKET_SNAPSHOT_ROOT` and the market engine's own ledger** live on
  another service. The founder side reads a committed snapshot bundle and
  says so; see `config/preview.yaml`.
